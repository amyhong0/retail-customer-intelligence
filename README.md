# 리테일 고객 인텔리전스와 개인화 추천

[시각화 포트폴리오 사이트](https://amyhong0.github.io/retail-customer-intelligence/)에서 사용 데이터·분석 방법·결과·인사이트·구현 구조를 확인할 수 있습니다.

dunnhumby 공식 공개 데이터 `The Complete Journey`의 원본 CSV를 분석해 고객 피처, 상품 추천, 캠페인 타겟 점수로 연결한 리테일 데이터 사이언스 프로젝트입니다. 거래 2,595,732행에서 정제 후 2,581,266행·고객 2,500명의 기록을 사용했습니다.

## 문제 정의와 비즈니스 가설

커머스 팀은 고객마다 어떤 상품을 보여줄지, 어떤 고객에게 캠페인을 제안할지 결정해야 합니다.

- **가설 1:** 고객의 구매 이력을 반영한 상품 추천은 전체 인기 상품 추천보다 재구매 고객에게 더 적합할 수 있습니다.
- **가설 2:** 최근 구매 시점, 구매 주기, 지출액, 선호 카테고리, 할인 반응으로 향후 28일 구매 가능성을 예측할 수 있습니다.
- **가설 3:** 시점 기준을 명확히 한 고객 피처를 추천·타겟팅·보고에 재사용할 수 있습니다.

추천 목록은 상품 노출 결정에, 구매 가능성 점수는 캠페인 대상 선정에 활용할 수 있습니다. 실제 캠페인 효과는 무작위 대조군 실험으로 확인해야 합니다.

## 프로젝트 구성

```text
src/data.py          데이터 검증·정제, 합성 데이터 생성
src/features.py      시점 기준 고객 피처 테이블
src/recommender.py   인기 상품 기준선과 상품 기반 협업 필터링
src/prediction.py    28일 구매 예측과 피처 중요도
src/insight_agent.py 선택형 LLM 인사이트 생성 경계
run_analysis.py      전체 분석 실행 스크립트
outputs/             지표, 그래프, 샘플 결과, 학습 모델
docs/architecture.md AWS·Spark 운영 확장안
```

고객 피처에는 RFM, 평균 주문 금액, 할인 민감도, 구매 간격, 주말 구매 비율, 카테고리 다양성, 선호 카테고리·브랜드, 구매 수량, 캠페인 배정 횟수가 포함됩니다. 정의와 갱신 주기는 `outputs/feature_dictionary.csv`에 저장됩니다.

## 실행 방법

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
python download_data.py
python run_analysis.py --max-items 1000
python -m unittest discover -s tests
```

공식 원본 데이터는 `python download_data.py`로 다운로드하고 `python run_analysis.py --max-items 1000`으로 분석합니다. [데이터 안내](data/README.md)에 출처와 파일 목록이 있습니다. `--synthetic` 옵션은 원본 데이터 없이 코드를 검증할 때만 사용하는 테스트용 생성기입니다.

## 공식 공개 데이터 분석 결과

공식 CSV에서 상품 기반 협업 필터링의 NDCG@10은 **0.1227**, 인기 상품 기준선은 **0.0396**이었습니다. Recall@10은 각각 **0.0834**와 **0.0367**입니다. 구매 예측 모델의 고객 단위 검증 ROC-AUC는 **0.8355**, 평균 정밀도는 **0.9510**입니다. 양성 구매 고객 비율 **0.8048**과 함께 해석합니다. 결과물은 [`outputs/`](outputs/)에 있습니다.

## 평가 방식

모든 고객의 DAY 683까지를 학습 기간으로 사용하고 이후 28일 중 첫 구매일의 상품으로 추천을 평가합니다. 학습 구매 수량 상위 1,000상품이 후보이며 재구매를 허용합니다. 후보 밖 상품도 정답에 포함합니다. 후보 상품은 평가 거래 행의 **33.8%**를 포함합니다. 고객 2,012명에 대해 Precision@10·Recall@10·NDCG@10을 계산했습니다. 구매 예측은 DAY 684–711의 구매 여부를 정답으로 하고 고객의 25%를 층화 분할해 평가했습니다. 원본 DAY에 임의의 요일을 부여하지 않아 주말 비율은 이번 모델에서 제외했습니다. 캠페인 피처는 START_DAY가 기준일 이하인 배정만 사용합니다.

## 해석 시 유의점

- 위 수치는 공식 공개 데이터의 한 기준일과 제한된 추천 후보에서 계산한 오프라인 평가입니다. 실제 운영 성과는 추가 실험으로 확인해야 합니다.
- 구매 성향과 캠페인의 추가 효과는 다릅니다. 캠페인 성과는 처치군·대조군 실험으로 측정해야 합니다.
- 세그먼트별 품질을 살피고 인구통계 정보의 활용은 해당 정책을 검토해야 합니다.
- 공개 원본 데이터는 용량과 재배포 조건을 고려해 저장소에 포함하지 않습니다.

## 면접 발표 순서: 5분

1. 두 가지 비즈니스 결정과 데이터 누수 방지를 위한 기준일을 설명합니다.
2. `customer_features_sample.csv`를 보여주며 피처 재사용의 가치를 설명합니다.
3. 추천 모델 지표와 신규 상품 노출·추천 범위의 절충을 논의합니다.
4. 주요 피처를 바탕으로 타겟 세그먼트를 제안하고 실험 방법을 설명합니다.
5. 운영 아키텍처와 성능 감시 지표로 마무리합니다.
